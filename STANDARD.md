# The Lab Standard

A lightweight, consistent structure for exploratory scientific projects — designed to stay readable
for **both you and AI coding agents across many sessions**, without becoming production software.

It blends three sources, modernized for 2025–26 agent-assisted work: Wilson et al.'s *Good Enough
Practices in Scientific Computing* (2017, the lean `data/` vs `results/` split), Cookiecutter Data
Science v2 (2024, installable package + numbered notebooks), and Anthropic's context-engineering
guidance + the AGENTS.md convention (a small always-read map that points to durable records).

---

## 1. Why this exists
Exploratory projects rot because every work session — especially every fresh agent session — starts
with no shared map and improvises its own layout. You get scripts, results, and logs scattered with
no provenance. The fix is **one structure, declared once, enforced on every session**, where the
agent reads the same map before it writes anything.

## 2. The structure
```
project/
├── AGENTS.md            # the map; read first. CLAUDE.md just imports it (@AGENTS.md)
├── README.md            # what this is + where the data lives
├── pyproject.toml       # editable package (pip install -e .)        [committed]
├── environment.yml      # conda/mamba env, the reproducible toolchain [committed]
├── justfile             # just run / submit / new-exp / index / test
├── .labstd              # marker that activates the path-guard hook
├── src/<pkg>/           # reusable, importable, tested library code  ← all reuse lives here
│   ├── config.py        #   YAML config + seed handling
│   ├── provenance.py    #   write manifest.json (git, env, seed, hashes, SLURM)
│   ├── tracking.py      #   MLflow local-store helpers
│   └── index.py         #   build runs.jsonl / scaffold experiments
├── data/
│   ├── raw/             # READ-ONLY inputs (gitignored; real data lives on shared store)
│   └── processed/       # derived data (gitignored, regenerable)
├── experiments/
│   ├── INDEX.md         # human/agent registry: what's been tried & outcome
│   ├── runs.jsonl       # machine-readable, regenerated by `just index`
│   └── exp-NNNN_slug/   # ONE self-contained run: config.yaml, run.py, manifest.json,
│                        #   metrics.json, README.md (hypothesis), figures/, slurm logs
├── notebooks/           # exploration only: <phase>.<n>-<initials>-<desc>.ipynb
└── docs/decisions/      # ADRs — numbered, immutable: why things are the way they are
```

## 3. The core rules
- **`data/raw/` is immutable.** Read it, copy it, never edit it. (`chmod -R a-w data/raw` + a hook.)
- **One run = one folder.** Everything a run produces — figures, metrics, logs, SLURM `.err/.out` —
  lives inside `experiments/exp-NNNN_slug/`. This is what kills the "junk-drawer `output/`" problem.
- **Reusable logic goes to `src/`**, not copy-pasted into scripts. Grep `src/` before writing.
- **Nothing in the repo root** except the declared config/doc files.
- **No hardcoded params.** Experiments read a `config.yaml`; the resolved config is saved per run.
- **Leave a trace.** Finished a run → update its `INDEX.md` row. Made a project-shaping choice → ADR.

## 4. Self-describing runs (provenance)
`run.py` calls `provenance.write_manifest()` and `tracking.run()` for you. Each run folder ends up
with a `manifest.json` (git commit + uncommitted diff, conda env lock, seed, input/output sha256,
host, SLURM job id) and metrics logged to a project-local MLflow store (`mlruns/`, no server/account;
browse later with `mlflow ui`). A result is therefore always traceable to the exact code+config+data
that produced it. `just index` regenerates `experiments/runs.jsonl` from the manifests.

## 5. Hybrid local ↔ HPC
The entry point is identical in both places:
- `just run <exp>` runs locally.
- `just submit <exp>` wraps the *same* command in `sbatch`, sending SLURM `.err/.out` into the run
  folder and recording the job id in the manifest.
- **Code + config** travel via git (`git pull` on the cluster). **Data** stays on shared store /
  scratch, referenced by a configurable path — never committed, never copied around blindly.

## 6. How it's enforced on every session (the layered model)
CLAUDE.md is *steering*, not a guarantee; only hooks hard-stop an agent. So enforcement is layered:

| Layer | Mechanism | Job |
|------|-----------|-----|
| Constitution | global `~/.claude/CLAUDE.md` block | applies to every session everywhere: read AGENTS.md + INDEX first; new work → experiments/; reuse src/; never root/raw |
| Rails        | this template (`/new-project`) | the structure exists from minute zero |
| Map          | per-project `AGENTS.md`        | the project-specific contract |
| Workflow     | `/new-experiment` skill        | encodes the run procedure so agents reuse it, not regenerate it |
| Guardrail    | PreToolUse hook `guard_paths.py` | the only hard stop: blocks writes to repo root + edits to data/raw |

## 6b. Consistency check & tests (keeping it honest, low-token)
Steering keeps agents *mostly* on track, but docs/structure can still drift. Two deterministic
guardrails — plain programs, ~0 LLM tokens — make it mechanical:
- **`just check`** (`src/<pkg>/check.py`) asserts structural invariants: every `experiments/exp-*/`
  has a README **and** an `INDEX.md` row; no dangling symlinks under `data/`; no stray files at the
  repo root. Add project-specific assertions as new `check_*` functions.
- **`pre-commit`** runs `just check` automatically on every `git commit` (one-time `pre-commit install`).
- **`just test`** (pytest) pins the **science**: a known-input → known-output test per load-bearing
  transform. Convention: **every ADR that encodes a computational rule gets a test that enforces it**
  (name the ADR in the test). The template ships `tests/test_example.py` showing the pattern.

No style linter by default — overkill for exploratory research code. (Add `ruff` later if you want
cheap bug-catching like undefined-name detection; it's a few lines in `.pre-commit-config.yaml`.)

## 7. Environment & tools (chosen defaults)
- **Env manager: conda/mamba** (needed for JAX/CUDA/compiled deps). `environment.yml` is committed.
- **Tracker: MLflow, local file store.** No server, no account; upgrade to a UI later only if needed.
- **Task runner: `just`.**
- Deliberately skipped as too heavy for solo exploration: Hydra (until you sweep), DVC (until data is
  large *and* changing), hosted W&B/cloud trackers, full MLOps platforms.

## 8. Multi-machine setup
`~/.claude/` is **per-machine** (not synced by your account). To get this on a new machine (e.g. the
HPC login node): `git clone <your-git>/lab-standard ~/.claude/lab-standard && bash
~/.claude/lab-standard/install.sh`. Update later with `git pull && bash install.sh`.

## 9. Starting a project / a run
- New project → `/new-project` (or copy `template/` and substitute `{{PROJECT}}`,`{{PKG}}`,`{{ENV}}`).
- New run → `/new-experiment` (or `just new-exp <slug>`).
